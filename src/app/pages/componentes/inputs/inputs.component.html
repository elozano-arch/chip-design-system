Inputs de formulario

Campos de texto sobre p-inputtext, p-password y p-iconfield de PrimeNG. Toda entrada debe tener label asociado, mensajes de error que expliquen cómo solucionar, y validación accesible. Alineado con el Kit UI 9.2 GOV.CO.

Qué debe llevar un campo

Label con for/id

<label for="x"> + id="x" (o inputId en componentes PrimeNG). Obligatorios con field-required.

Ayuda y error

<small> de ayuda con aria-describedby; el error explica cómo solucionar, no solo "inválido".

Validación accesible

aria-required, aria-invalid y borde de color distinto para válido/inválido (ng-invalid ng-dirty).

Iconos bien puestos

Iconos dentro del input siempre con p-iconfield + p-inputicon, nunca position:absolute.

Texto con ayuda

El campo base: label, input y un <small> de ayuda asociado con aria-describedby.

02

Con validación (error en vivo)

Escribe algo sin @ y sal del campo para ver el error. El borde se pone rojo y el mensaje explica qué corregir.

@if (correoInvalido) { Escribe un correo válido, debe incluir @ (ej: nombre@dominio.gov.co). }
03

Con icono (p-iconfield)

Campos de búsqueda o con icono indicativo. El icono va dentro del flujo con p-iconfield, no posicionado a mano.

04

Contraseña (p-password)

Con toggle "mostrar/ocultar" accesible y medidor de fortaleza. Usado en login y cambio de contraseña.

05

Área de texto (textarea)

Para texto largo (observaciones, comentarios). Con maxlength y filas iniciales.
